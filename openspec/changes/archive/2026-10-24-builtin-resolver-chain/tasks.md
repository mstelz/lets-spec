## Deviations Ledger

- 1.2: `pnpm check` failed after 1.1, because the old `lookup.test.ts` builds configs that list paths. Its `chain` helper casts them to resolver names until 2.1 replaces those tests.
- 1.4: `Deps.nodePath` stays until 2.1, because the old lookup runs the default program with it until then. The fixture keeps the fake program beside the fake adapters until 2.2 to 2.4 move the command tests. Between 1.1 and 2.4 the old command tests that list paths fail; the branch is pushed only once the whole suite passes.
- 2.1: `withModels` takes the models and the call, not the adapter: the call already holds the adapter. It runs each call through `inAdapter`. `pick` is async, because it runs `detect()` through `inAdapter` too.
- 2.2: the `--model` check is `checkModels` in `lookup.ts`, so `handoff.ts` shares it. Every adapter returns a handle from `run`, so the old "no handle means no finish" test goes.
- 2.4: `instructions` no longer finds the repo root, because `options` takes no folder. The fixture's process plumbing (the fake program, `LETS_SPEC_RESOLVER`, the default program in a temporary folder) goes, and so does `Io.isExecutable`, which nothing calls now.
- 3.1: `cli.test.ts` also keeps its usage-error tests that never reached a resolver (`--for`, `--model` order), now run against the no-config `subagent`, and the sh example's scenario, which now exits 2 through the real program.
- 3.2: the README's *Install a resolver* is now *The resolvers*, with a row for `subagent` too. Its *Write your own* section goes, because `lets` can no longer run a resolver of yours, and it linked the contract document. The requirements table names what the resolvers need, not a resolver to install. The resolver pages' *Check that it works* use `lets delegate review instructions` in place of `lets delegate verify` on an installed program.
